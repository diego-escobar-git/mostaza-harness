## Why these changes

The reviewed [vLLM v0.19.1 worker source](https://github.com/vllm-project/vllm/blob/v0.19.1/vllm/v1/worker/gpu_worker.py)
sets the V1 sampler warm-up request count to the smaller of max_num_seqs and
max_num_batched_tokens. A capacity of one matches this experiment's serial
agent workload. The same source deducts estimated CUDA graph memory from the
KV allowance when the profiling flag is enabled; [its environment reader](https://github.com/vllm-project/vllm/blob/v0.19.1/vllm/envs.py)
otherwise defaults that flag to false and the engine-ready timeout to 600 s.
The native exception also specifically recommends lowering max_num_seqs or
memory utilization. We choose the workload-derived capacity limit and retain
0.90 rather than introduce an additional uncalibrated memory fraction.

[PyTorch 2.10 CUDA documentation](https://docs.pytorch.org/docs/2.10/notes/cuda.html#optimizing-memory-usage-with-pytorch-alloc-conf)
describes PYTORCH_CUDA_ALLOC_CONF as an alias of PYTORCH_ALLOC_CONF and documents
expandable_segments as an experimental allocator option. This is a configured
mitigation, not evidence that allocator fragmentation caused the observed OOM.
The restored timeout allows initialization time; it does not repair memory.
Upstream source receipts are in official-review.json. Version labels alone do
not prove organizer wheel source identity; the candidate records installed hashes.

  real start path and returns it unchanged. Only the 15 allowed keys are written;
  credentials and arbitrary inherited variables are excluded. Drift aborts spawn.
- startup-configuration.json records that mapping, common config, Python/package
  versions and installed vLLM source hashes. This covers configured child values;
  worker-internal allocator state remains null with a reason.
- Bounded nvidia-smi point samples before spawn and after native health readiness
  report per-device total/used/free in MiB. These include other driver-visible
  allocations; they are not peak memory, model-only memory or PyTorch counters.
  Missing, malformed or incomplete readings remain null with reasons.
- Persistent five-second observation and native logs retain timings, health,
  process state and errors. Parent liveness is never model readiness. The browser
  operator cancels on fatal engine errors even if the parent stays RUNNING.
- Both arms share this profile. This is a serving correction plus budget change
  relative to phase 1; do not attribute historical differences solely to budget,
  retrieval strategy or any one correction. There is no GPU proof of the fix yet.
